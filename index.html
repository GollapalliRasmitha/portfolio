2 real bugs my own security tool found

70 / 75

A rate-limit race condition

My attack simulator sent 75 parallel sign-in requests against a limit of 20 a minute – 70 got through, because the counter was read and written in two steps. Fixed with an atomic Redis counter: now exactly 20 pass.

1 IP

Every visitor looked like a proxy

After going live, alerts showed a Cloudflare address for every visitor, so they shared one sign-in limit. I measured the proxy chain and fixed it with a secret-signed header and the right hop count.
